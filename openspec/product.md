# プロダクト概要

## 目的

本プロジェクトは、モダンな Python アプリケーション、特にコマンドラインインターフェース（CLI）を迅速かつ一貫して開発するためのテンプレートである。
Python のパッケージング、依存関係管理、設定、ログ、見やすいターミナル出力、テスト、静的解析、仕様駆動開発（SDD）の基盤を提供し、個別プロダクトの実装に集中できる状態を目指す。

## スコープ

### 提供するもの

- `src` レイアウトで管理する Python アプリケーションパッケージと CLI エントリーポイントの雛形
- `uv` による Python と依存関係の再現可能な管理
- 型安全な設定読み込み、構造化されたログ出力、リッチなターミナル表示を採用できる実行時基盤
- pytest、Ruff、Pyright、pre-commit、Safety による品質保証の基盤
- OpenSpec を利用した、提案から仕様、設計、タスク、実装、検証、アーカイブまでの SDD 運用

### 提供しないもの

- 特定の業務ドメイン、外部 API、データベース、Web UI の完成済み実装
- 認証、認可、永続化、クラウドデプロイなど、用途ごとに選択すべきアーキテクチャの強制
- 機密情報、実運用環境の設定値、利用者データのリポジトリへの保存

## 利用者

- 新しい Python アプリケーションを立ち上げる開発者
- テンプレートを基に CLI ツールや自動化スクリプトを実装する開発チーム
- OpenSpec の変更成果物を利用して、要件・設計・実装をレビューする関係者

## 中核機能

| 機能 | 提供する価値 | 主な利用者 |
| --- | --- | --- |
| CLI 基盤 | 型ヒントを用いてコマンド、引数、オプション、ヘルプを定義できる | CLI 利用者・開発者 |
| 設定管理 | 環境変数や `.env` を型検証してアプリケーション設定として利用できる | 開発者・運用者 |
| ログ・表示 | 診断可能なログと、読みやすいターミナル出力を実装できる | CLI 利用者・運用者 |
| 品質保証 | テスト、静的解析、フォーマット、脆弱性確認を自動実行できる | 開発者・レビュアー |
| SDD 運用 | 変更の意図、振る舞い、設計、実施項目を追跡可能にする | 開発者・関係者 |

## 代表ユースケース

1. 開発者がテンプレートを複製し、`pyproject.toml` のプロジェクト情報と `src/<package_name>/` を用途に合わせて変更する。
2. 開発者が OpenSpec の変更を作成し、要件を EARS 記法で定義してから設計・タスクを作成する。
3. CLI 利用者がコマンドを実行し、引数・設定に基づく処理結果、進捗、エラーをターミナルで確認する。
4. 開発者が実装後に lint、format、型チェック、テスト、依存関係の脆弱性確認を実行する。
5. レビュアーが OpenSpec の仕様、設計、タスク、テスト結果を確認して変更を承認する。

## ドメインと用語

| 用語 | 定義 |
| --- | --- |
| アプリケーション | `src/python_template/` 配下に実装する Python パッケージ。テンプレート利用時は用途に応じて名称を変更する。 |
| CLI | 利用者がターミナルから実行するコマンドラインインターフェース。 |
| 設定 | 環境変数、`.env`、または明示的な引数から読み込む、実行環境ごとに変化し得る値。 |
| 変更 | OpenSpec で管理する、ユーザーまたは外部システムから観測できる振る舞いの追加・変更・廃止。 |
| capability | まとまりのある振る舞いを表す OpenSpec の仕様単位。 |
| 仕様 | システムが満たすべき観測可能な振る舞いを規定した文書。実装方法は含めない。 |

## プロダクト上の原則

- 利用者に見える振る舞いは、実装前に仕様として明文化し、テストで検証可能にする。
- 設定値・秘密情報はコードやリポジトリに埋め込まず、環境ごとに安全に注入する。
- エラーは握りつぶさず、利用者への結果と運用者が調査できる情報を用途に応じて提供する。
- テンプレートの共通基盤は小さく保ち、特定ドメインの依存関係や複雑性は必要になった変更で追加する。

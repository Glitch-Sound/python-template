# 技術スタック

## 実行環境とパッケージング

| 項目 | 採用技術 | 方針 |
| --- | --- | --- |
| 言語 | Python 3.13 | `.python-version` と `pyproject.toml` の `requires-python` に従う。互換性が必要な場合を除き、Python 3.13 の標準機能と構文を使用する。 |
| パッケージ管理 | uv | Python 実行、仮想環境、依存関係、ロックファイルを管理する。パッケージの追加・削除は `uv add` / `uv remove` を使い、`uv.lock` を更新する。 |
| ビルド | uv_build | `pyproject.toml` の `[build-system]` で定義されたビルドバックエンドを維持する。 |
| パッケージ配置 | src レイアウト | 実行時コードは `src/python_template/` に置き、リポジトリ直下からの偶発的な import に依存しない。 |
| CLI エントリーポイント | `[project.scripts]` | `python-template = "python_template:main"` を現行の公開コマンドとする。変更時は README とテストも更新する。 |

## アーキテクチャ

現在のテンプレートは、単一の Python パッケージと CLI エントリーポイントから始まる小規模なアプリケーション構成である。機能追加時は、以下の責務分離を基本とする。

```text
CLI / 表示層
    ├── 引数・オプションの受け取り、利用者への結果表示、終了コード
    └── アプリケーションサービスの呼び出し
アプリケーション層
    ├── ユースケースの実行順序、入力検証、エラーの変換
    └── ドメイン・インフラストラクチャ層の調整
ドメイン層（必要な場合）
    └── 業務ルール、型、値オブジェクト。外部 I/O に依存しない
インフラストラクチャ層（必要な場合）
    └── 環境変数、ファイル、ネットワーク、外部 API、永続化
```

- 小規模な機能は過剰な階層化を避け、責務が混ざらない最小のモジュール構成にする。
- CLI、設定、ログ、外部 I/O は境界として扱い、ドメインロジックから直接参照しない。
- 外部 API や永続化を導入する場合は、呼び出し側が依存するインターフェースと、失敗・再試行・タイムアウト・認証の方針を設計で定義する。
- 非同期処理、Web サーバー、データベース、キューは現時点の標準構成に含まない。導入は OpenSpec の変更として必要性、代替案、運用影響を検討してから行う。

## 主要ライブラリ

### 実行時依存関係

| ライブラリ | 用途 | 利用方針 |
| --- | --- | --- |
| Typer | 型ヒントを利用した CLI のコマンド、引数、オプション、ヘルプの定義 | 公開 CLI の定義に使用する。引数の型・必須性・既定値・エラーを明示する。 |
| Pydantic Settings | 環境変数や `.env` からの設定読み込みと型検証 | 設定は型付きの設定クラスに集約する。機密値をログ・例外・テストデータに出力しない。 |
| Loguru | アプリケーションログの出力と管理 | ログレベルとメッセージを用途に応じて使い分け、例外時は調査に必要な文脈を残す。利用者向け表示の代替にしない。 |
| Rich | 色付きテキスト、テーブル、進捗、読みやすい例外表示などのターミナル出力 | CLI 利用者に表示する結果・進捗・エラーを読みやすくするために使用する。非対話環境・リダイレクト時の出力形式とテスト容易性を考慮する。 |

### 開発時依存関係

| ライブラリ | 用途 | 利用方針 |
| --- | --- | --- |
| pytest | 単体テスト・結合テスト | テストは `tests/` に置き、成功・失敗・境界条件を検証する。 |
| pytest-mock | モックによる依存境界の置き換え | 外部 I/O などの依存を置き換えるために使用し、実装の内部呼び出しへの過度な依存を避ける。 |
| Ruff | lint とフォーマット | `pyproject.toml` の設定を唯一の定義元とし、lint と format の両方を実行する。 |
| Pyright | 静的型チェック | `src` と `tests` を対象に standard モードで検査する。型エラーを `# type: ignore` で回避する場合は理由と対象を最小化する。 |
| pre-commit | コミット前の品質チェック実行 | 定義済みフックを有効化し、変更をコミットする前に実行する。 |
| Safety | 依存関係の既知脆弱性確認 | 依存関係更新時とコミット前に確認し、検出結果の対応方針を記録する。 |

OpenSpec は Node.js の開発依存関係（`@fission-ai/openspec`）として `package.json` で管理する。Node.js の依存関係更新には npm を使用し、`package-lock.json` を同時に更新する。

## 開発基準

### コード品質

- すべての新規・変更 Python コードに、公開 API と複雑なロジックを理解するための型ヒントを付ける。
- Ruff の対象バージョンは Python 3.13 とし、設定済みの `E4`、`E7`、`E9`、`F`、`I`、`B`、`S`、`SIM`、`UP` ルールに従う。テスト内の `assert` は許可する。
- フォーマットは Ruff に委ね、手動の書式調整で設定と競合させない。
- 設定値・パス・タイムアウト・ログレベルなどを無根拠なマジック値として散在させない。用途と既定値が明確な定数または設定として定義する。
- 例外を握りつぶさない。回復できない失敗は十分な文脈を伴って呼び出し元へ伝播し、CLI では利用者が次に取る行動を理解できる結果を表示する。
- `print` は最小の雛形または単純な CLI 出力に限る。表・進捗・強調・例外表示が必要な対話的出力には Rich を用いる。診断情報は Loguru を用いる。

### 依存関係と設定

- 新しい依存関係は、標準ライブラリまたは既存ライブラリで満たせない理由、ライセンス・保守性・脆弱性・追加サイズへの影響を確認してから追加する。
- 実行時依存関係と開発時依存関係を分離する。テスト・lint・型検査専用のパッケージは development dependency group に追加する。
- 秘密情報はソースコード、テスト、OpenSpec 成果物、ログに含めない。設定のサンプルには安全なプレースホルダーだけを使用する。
- ロックファイルを手編集しない。Python は `uv`、Node.js は `npm` に更新を委ねる。

## テストと検証

### テスト方針

- pytest の対象は `tests/` とし、`--strict-config` と `--strict-markers` を維持する。
- 要件ごとに少なくとも1つのテストまたは明確な手動検証手順を対応付ける。正常系だけでなく、入力不正、境界値、権限、外部依存の失敗など、仕様で定義した分岐を検証する。
- CLI テストでは、標準出力・標準エラー・終了コード・永続状態など、利用者が観測できる結果を検証する。
- テストは独立して再実行可能にし、ネットワーク、実時間、実環境の認証情報に依存しない。必要な境界はモックまたはテスト用の実装に置き換える。

### 必須コマンド

実装または設定を変更した後は、原則として次を実行する。

```bash
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked pyright
uv run --locked pytest
uv run --locked pre-commit run --all-files
```

依存関係を変更した場合は、加えて `uv sync --locked`（Python）または `npm ci`（Node.js）で再現可能に同期できることを確認する。OpenSpec の変更はアーカイブ前に `openspec validate <change-name> --strict` を実行する。
